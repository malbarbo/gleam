# builtins-wasm ABI

Contract between the WebAssembly code generator (`compiler-core/src/webassembly.rs`),
the Rust runtime in this crate and the `@external(webassembly, ...)` annotations of
the standard library. The design rationale lives in the stdlib proposal
(`WASM_PRIMITIVES_RUST.md`); this file only fixes names, types and memory layout.

There are two external modules:

- `"rust"`: functions exported by this crate. The compiler generates the glue
  that copies Gleam values into linear memory and back, from the Gleam type of
  the external function (section *Glue*).
- `"builtins"`: functions generated by the compiler itself, as wasm code that
  works directly on GC values (section *Compiler builtins*).

## Glue (`"rust"` module)

### Configuration

The start function calls `_config(int_bits: i32, float_bits: i32)` once, before
anything else, with 32 or 64 for each. Rust uses it to check `Int` overflow in
parsers and to format/parse `Float` as `f32` when `float_bits == 32`.

### Memory

Rust owns a bump arena in linear memory, which is also its global allocator.

| Export | Signature | Meaning |
|---|---|---|
| `cabi_realloc` | `(old_ptr: i32, old_size: i32, align: i32, new_size: i32) -> i32` | allocate in the arena (grows memory as needed, traps when it cannot) |
| `_arena_mark` | `() -> i32` | current top of the arena |
| `_arena_release` | `(mark: i32)` | reset the top to `mark` |
| `_heap_base` | `() -> i32` | top of the arena rounded up to 16; scratch memory the code generator may write to without allocating |

Every glue call does: `mark = _arena_mark()`, lower the arguments (allocating
with `cabi_realloc`), allocate the return area, call, lift the result, then
`_arena_release(mark)`. Calls may nest (a repr calls Gleam code that calls Rust),
so the arena is never reset to zero.

`_heap_base` scratch memory is not allocated: anything that allocates in the
arena (any glue call) while the scratch is in use may overwrite it.

### Layout of values in memory

All sizes are multiples of 8 and every value is 8-aligned. Little endian.

| Gleam type | Size | Layout |
|---|---|---|
| `Int` | 8 | `i64` (sign-extended from `i32` when `Int` is 32 bits) |
| `Float` | 8 | `f64` (widened from `f32` when `Float` is 32 bits) |
| `Bool` | 8 | `u32` 0/1 at +0 |
| `UtfCodepoint` | 8 | `u32` at +0 |
| `Nil` | 0 | — |
| `String` | 8 | `ptr: u32` at +0, `len: u32` at +4 (bytes, valid UTF-8) |
| `BitArray` | 16 | `ptr: u32` at +0, `byte_len: u32` at +4, `bit_len: u32` at +8 |
| `List(T)` | 8 | `ptr: u32` at +0, `count: u32` at +4; `count` elements of `size(T)` each |
| `#(A, B, ...)` | `Σ size` | fields in order |
| `Result(T, E)` | `8 + max(size T, size E)` | `u32` tag at +0 (0 = Ok, 1 = Error), payload at +8 |

A pointer returned by Rust may point anywhere in the arena, including into the
argument bytes (for example `string_trim` may return a sub-slice of its input).
The pointer of an empty `String`, `BitArray` or `List` may be any value.
A `BitArray` returned by Rust always has `bit_len == 8 * byte_len`. In a
`BitArray` argument a partial last byte holds its bits in the most significant
positions; the unused low bits may be anything and are ignored.

### Parameters and results

Parameters are flattened into wasm values:

| Gleam type | wasm params |
|---|---|
| `Int` | `i64` |
| `Float` | `f64` |
| `Bool`, `UtfCodepoint` | `i32` |
| `Nil` | none |
| `String` | `ptr: i32, len: i32` |
| `BitArray` | `ptr: i32, byte_len: i32, bit_len: i32` |
| `List(T)` | `ptr: i32, count: i32` (elements laid out as above) |

Any other parameter type is a compile error.

Results of type `Int`, `Float`, `Bool`, `UtfCodepoint` are returned directly as
`i64`, `f64`, `i32`, `i32`; `Nil` returns nothing. Any other result type adds a
last parameter `ret: i32`, pointing to an 8-aligned area of `size(T)` bytes that
Rust fills with the layout above.

### Panics

A Rust panic writes `panic: <message>\n` to stderr and traps (`unreachable`).
Only literal messages are printed (`panic!("invalid code point")`); for a
message with arguments the source location is printed instead, because
formatting would bring `core::fmt` into the module.

### Raw exports used by compiler builtins

Not callable from Gleam; the compiler calls them from generated code.

| Export | Signature | Meaning |
|---|---|---|
| `_grapheme_prefix_len` | `(ptr: i32, len: i32, complete: i32) -> i32` | byte length of the first grapheme of the window; `-1` when `complete == 0` and the grapheme reaches the end of the window (it may continue past it), the window cuts a UTF-8 sequence before the first grapheme ends, or the window is empty; with `complete != 0` the window is the whole string and `""` gives `0` |
| `_float_repr` | `(f: f64, ptr: i32) -> i32` | writes `float_to_string(f)` at `ptr`, returns the length (used by `_inspect`) |

The older exports (`_print`, `_exit`, `_i32_to_str`, `_i64_to_str`, `_f32_to_str`,
`_f64_to_str`, `_i32_parse`, `_i64_parse`, `_f32_parse`, `_f64_parse`,
`_i32_is_codepoint`, `_i64_is_codepoint`, `_heap_base`) keep their signatures.
`_f32_to_str`/`_f64_to_str` now write the `float_to_string` text (for `f32` and
`f64` respectively) and `_i32_parse`/`_i64_parse` use the `from_str` grammar.

Indirect calls are fine (`memchr::memmem` uses them): the code generator keeps
the active element segments that fill the table. The panic handler still avoids
`core::fmt`, which would bring a lot of code into every program that can panic.

The code generator finds the exports by function name (the name section), so
every export must stay a distinct function (LTO may otherwise merge identical
bodies under one name).

The module imports `fd_write`, `proc_exit` and `random_get` from
`wasi_snapshot_preview1`.

## Compiler builtins (`"builtins"` module)

Generated wasm, no linear memory. `Int` and `Float` follow the configured width.

**Int**

| Name | Gleam type | Semantics |
|---|---|---|
| `_int_bitwise_and` / `_or` / `_exclusive_or` | `fn(Int, Int) -> Int` | one instruction |
| `_int_bitwise_not` | `fn(Int) -> Int` | `xor -1` |
| `_int_bitwise_shift_left` | `fn(Int, Int) -> Int` | shift ≥ width gives 0; negative shift is a right shift |
| `_int_bitwise_shift_right` | `fn(Int, Int) -> Int` | arithmetic; shift ≥ width gives 0 or -1; negative shift is a left shift |
| `_int_to_float` | `fn(Int) -> Float` | `convert_s` |

**Float**

| Name | Gleam type | Semantics |
|---|---|---|
| `_float_floor` / `_float_ceiling` | `fn(Float) -> Float` | native |
| `_float_truncate` | `fn(Float) -> Int` | `trunc_sat_s` |
| `_float_round` | `fn(Float) -> Int` | half away from zero: `t = trunc(|x|); r = t + (|x| - t >= 0.5)`, sign restored, then `trunc_sat_s` |
| `_float_square_root` | `fn(Float) -> Float` | native |

**String** (bytes; `String` is a view `{ bytes, off, len }`, so slices are `O(1)`)

A slice of up to 64 bytes, or smaller than a quarter of the byte array it
comes from, is copied; a bigger one shares the array.

| `_string_starts_with` / `_string_ends_with` | `fn(String, String) -> Bool` | |

Also planned: the external type `"builtins", "AnyRef"` for the payload of
`DOther`; externals pointing at Gleam modules (`@external(webassembly,
"gleam/internal/wasm/champ", "insert")`, for functions and types); and type
hooks, so that `==`, `_hash` and `_inspect` of `Dict` call the `equal`,
`hash_dict` and `inspect` functions of its module.
